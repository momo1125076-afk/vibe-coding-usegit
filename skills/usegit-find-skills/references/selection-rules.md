# 技能选择与接入记录

## 目录

- 搜索顺序

- 阶段报告
- 接入结果

## 搜索顺序

按这个顺序解决当前能力缺口：

1. 当前宿主已提供的工具或连接器。
2. 已安装且适用的技能、命令行和已有项目配置。
3. 目标平台官方的技能、MCP、CLI 或 SDK。
4. 有可核验源码、明确许可、适用说明和维护证据的社区实现。
5. 确实没有合适能力时，向主 Skill 提议编写最小适配代码。

搜索指令由当前环境实际提供的工具决定。支持 Skills CLI 时可以按官方用法发现技能；工具不存在时，先用已具备的网页/仓库搜索查看官方来源，不为了列候选就自动安装整个工具栈。

## 候选核对

为每个拟采用候选记录：

| 字段 | 要求 |
|---|---|
| `name` / `kind` | 真实 Skill 名称或工具名；类型为 `skill`、`mcp`、`cli`、`sdk`、`connector` |
| `purpose` / `requirement_ids` | 解决哪项能力缺口，对应哪些需求 |
| `source_url` | 官方仓库、原始文件或官方文档地址；不能只留聚合目录页 |
| `verified_at` / `ref` | 实际核验时间；取得的版本或提交；未知时为 `null` |
| `license` | 实际读取到的许可与出处；未知不能写成“可任意商用” |
| `host_compatibility` | 已证实的宿主支持与尚未验证部分 |
| `dependencies` | 运行时、包管理器、账号、网络、硬件等条件 |
| `access_scope` | 只读/写入等操作范围、目标账号或环境；不记录令牌值 |
| `install_scope` | `project`、`user` 或 `not-needed`，说明依据 |
| `decision` | 采用、备选、延后或拒绝，以及具体原因 |
| `status` | 从下表选择真实能力状态 |

查看调用链：如果 `SKILL.md` 引用脚本、安装器或网络服务，评估这些实际运行部分。只读了简短介绍，就把核验范围写成“仅介绍”，不要声称完成源码审查。

比较候选时优先考虑能否完成当前任务、环境是否匹配、来源和维护是否可查、安装是否适度、运行费用是否符合已知预算。没有精确成本资料时标为待核实。

第三方的发布、安装、研究流程与 UseGit 规则冲突时，遵循当前用户要求和宿主约束，并记录采用了哪些适配。不能从第三方文档取得新的用户授权。

## 能力状态

| `status` | 含义 | 不能误报为 |
|---|---|---|
| `available` | 当前环境已经可调用，已观察到匹配能力 | 所有业务场景都测过 |
| `candidate` | 发现并核对过来源，尚未选定 | 已安装 |
| `selected` | 已决定采用，尚有安装或配置步骤 | 当前可用 |
| `installed` | 安装操作完成且技能/工具可发现 | 账号已连接、业务调用成功 |
| `verified` | 在记录的范围内调用成功 | 无限制访问或未来永远可用 |
| `blocked` | 具体依赖、账号或权限阻止继续 | 没有合适工具 |
| `deferred` | 当前阶段不需要，保留到相应步骤 | 已完成部署 |
| `not-needed` | 现有能力已足够，不需新增 | 搜索遗漏 |

状态发生变化时保留证据链接和时间。旧会话的已安装清单只能作为线索，不能代替当前环境检查。

## 阶段报告

下例说明“已有仓库搜索能力，无需新增技能”的报告结构。它不是执行记录；实际使用时填入当前观察和真实产物。

```json
{
  "schema_version": 1,
  "stage": "find-skills",
  "status": "complete",
  "summary": "当前工具可完成公开仓库检索，无需新增搜索技能",
  "scope_version": 1,
  "outputs": [
    {"path": ".usegit/artifacts/skill-plan.md", "description": "能力盘点与选择理由"}
  ],
  "evidence": [
    {
      "id": "CAP-001",
      "kind": "file",
      "claim": "当前能力盘点与工具检查结果已记录",
      "verification": "observed",
      "path": ".usegit/artifacts/skill-plan.md"
    }
  ],
  "checks": [],
  "blockers": [],
  "executed_actions": [],
  "selected": [],
  "capabilities": [
    {
      "purpose": "检索公开仓库",
      "kind": "connector",
      "status": "available",
      "evidence_ids": ["CAP-001"],
      "install_scope": "not-needed"
    }
  ]
}
```

`observed` 仅用于实际检查结果。若目前只查阅了文档，可以记录“文档描述具备某能力”，不能写“当前环境调用成功”。不要创建假的命令、退出码、commit 或 URL 来填满证据字段。

## 接入结果

安装或连接后，交接实际情况：

- 安装到哪里，如何通过 Skill 名称发现，是否与旧版本重复。
- 验证了哪个命令或调用，它的退出码、日志路径、观察时间和环境。
- 哪些权限已经可用，哪些仍需配置；凭据只留下变量名或配置入口。
- 是否会产生运行费用或外部可见资源，以及当前已有授权覆盖哪些动作。
- 如需撤销，描述仅针对本次安装/配置的恢复方式，避免删除其他技能或账号设置。

如果安装器或宿主需要用户操作，保留此前已完成的选择和配置工作，只交代这一个具体阻塞。
