# 验收与证据规则

## 核心业务优先

从需求编号出发选择检查，不以“测试数量多”替代功能覆盖。一个业务需求可能需要多个平台的检查。检查结果固定为 `pass / fail / not-run / blocked / not-applicable`。

| 场景 | 建议检查 |
|---|---|
| 表单/列表/搜索 | 正常输入、无数据、无结果、非法输入、重复点击、保存与再次读取 |
| 登录/权限 | 登录、退出、过期、拒绝授权、错误角色访问；仅与约定功能有关时执行 |
| 订单/支付 | 创建与查询、取消/失败、重复回调、服务端最终状态；真实付费操作需已有明确授权 |
| 离线 | 首次启动是否可用、断网读写、重启、恢复联网、同步冲突与恢复 |
| 上传/导出 | 允许格式、大小限制、失败恢复、内容正确、权限和下载位置 |
| AI | 固定输入/模型/参数、真实响应、超时/限流/不可用、数据来源与引用、实际资源消耗 |

## 分平台不能替代的检查

| 平台 | 最低证据形态 | 常见错误结论 |
|---|---|---|
| Web | 实际部署或本地约定环境的页面与业务操作 | 首页 200 就算所有功能正常 |
| PWA | 目标浏览器的安装/离线/更新检查（仅对已承诺能力） | manifest 存在就算离线应用完成 |
| 微信/其他小程序 | 对应工具或宿主环境、AppID/版本、实际页面与业务结果 | 用 H5 截图替代小程序测试 |
| iOS/Android | 对应模拟器/真机、包版本、安装启动与功能结果 | 只编译 Web 版本就算 App 可用 |
| 桌面 | 指定 OS/架构安装包的安装、启动、必要升级/卸载结果 | 一个系统通过就声称三个系统通过 |
| API/后端 | 真实请求、预期响应、持久化与鉴权结果 | 进程存活就算业务正常 |
| 扩展 | 在目标浏览器真实加载、权限与功能结果 | 普通网页运行替代扩展安装 |
| 自动化 | 实际输入输出、重复运行与失败恢复结果 | 只有脚本内容，没有执行记录 |
| AI 服务 | 实际模型/服务调用与已承诺指标 | 硬编码回答替代模型能力 |
| 游戏 | 目标构建可玩、输入/存档/关键玩法结果 | 编辑器截图替代可玩构建 |
| IoT | 实际设备、固件、协议交互与必要异常恢复 | mock 串口或编译通过替代硬件联调 |

以上为 UseGit 的验收设计，不代表本仓库已经为所有平台提供自动测试驱动。使用当前宿主可用工具执行；缺少工具时保留未测项。

## 版本与复现

每条证据带环境和时间。代码、构建配置、模型、数据库结构或外部 API 变更会使相关旧证据失效；只重复受影响且仍有风险的检查。单次通过不能推导未测试的设备、操作系统和负载范围。

录屏和截图用于说明界面与操作，日志和数据检查用于核对后台结果。不能互相覆盖的证据并列保留。人工结果引用来源和步骤；Agent 未亲自执行时明确写“用户提供的测试记录”。

## 客户交付说明应回答

1. 从哪里打开、安装或调用？适用哪些设备？
2. 已完成哪些原始需求？逐项对应需求编号。
3. 哪些结果由实际测试支持？测试在哪个版本和环境进行？
4. 哪些功能依赖外部账号、审核、付费服务或真实硬件？当前状态是什么？
5. 日后如何启动、更新、备份和恢复？遇到问题查看哪里？

状态陈述用具体词：已构建、已在某环境运行、已上传开发版、审核中、已公开发布、已验证某项能力。避免用一句“全部搞定”覆盖仍需人工完成的环节。
