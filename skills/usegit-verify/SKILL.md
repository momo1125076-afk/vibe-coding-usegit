# UseGit 验证与交付

从客户要完成的任务出发检查结果。将“文件存在、构建成功、部署成功、业务可用”分别验证。

## 接收输入

读取 `.usegit/artifacts/discover.json` 顶层 `requirements` 中的需求编号、`priority` 与 `acceptance`，以及目标平台/环境、交付范围、源码版本、产物校验值和已知限制。`preview / release` 模式读取 `.usegit/artifacts/deploy.json`；`local` 模式直接读取运行与改造产物，不要求先部署。按名称接收 `vibe-coding-usegit` 的上下文，不依赖固定兄弟目录。仅需本地交付时，以实际运行/构建产物为对象。

按需读取 [验收与证据规则](references/acceptance.md)。没有清晰验收标准时，先根据已确认需求提出可执行检查，明确假设；不要追溯性地删掉失败要求来获得通过。

## 执行

1. **固定受测对象。** 核对 commit、构建版本、安装包校验值、部署 URL/ID、目标环境与时间。变更源码或配置后，检查旧证据是否还适用；对受影响要求重新验证。
2. **建立需求清单。** 覆盖需求清单中每一个 `priority: "must"` 的需求；`should / could` 的取舍另记，不偷偷降级未完成的 must。每个必须满足的需求至少对应一条检查。选择最能发现问题的真实使用步骤，包含关键失败分支；同时记录自动检查和人工检查的边界。
3. **验证核心业务。** 使用隔离测试数据完成输入、提交、持久化、重新读取或重启后的结果。需要权限、支付、网络、设备等能力时，在相应环境实际检查；模拟替身单独记录。
4. **验证交付物。** Web 检查实际访问与路由，App/桌面检查目标系统安装启动与升级，小程序检查目标宿主与发布阶段，API/AI 检查真实请求，硬件检查实际通信。只核验约定的平台，不夸大覆盖范围。
5. **处理问题。** 功能或界面问题交回 `usegit-adapt`，构建/部署问题交回 `usegit-deploy`，基线问题交回 `usegit-run`。附最短复现、预期/实际结果、日志与相关需求编号。遵守主技能重试预算，超出预算就保留明确阻塞。
6. **形成交付。** 告诉客户如何访问/安装、已实现什么、验证到什么程度、尚缺什么，以及启动/更新/恢复方法。保留源代码位置、上游来源、必要配置名称和版本，不包含秘密值。

## 证据判断

`evidence` 使用唯一 `id`，并写明 `kind: file | command | url | manual`、实际 `claim` 与 `verification: observed | simulated | not-run`。

- 命令证据：附命令、工作目录/环境、退出码、日志路径、commit 和观察时间；日志文件必须能核查对应结果。
- 页面/接口证据：附真实 URL 或平台标识、环境、实际操作与结果；访问到首页不能代替全部需求通过。
- 人工证据：记录操作者提供的具体步骤、设备、版本、日期和结果；若 Agent 无法复核，明确标注为用户报告，不伪称亲自观测。
- 模拟/未执行：说明替身是什么、覆盖什么、没有覆盖什么。截图、mock、文档和推演不能替代目标平台的关键能力验证。

不要在交付文档里保留登录凭据、用户真实业务数据或可接管资源的链接。必要的敏感截图先遮挡无关信息。

## 输出与完成条件

写入 `.usegit/artifacts/verify.json` 和客户可读 `verify.md`，证据放入 `.usegit/evidence/verify/`。使用统一契约 `schema_version: 1`、`stage: "verify"`、`status`、`summary`、`outputs`、`evidence`、`checks`、`blockers`、`executed_actions`；可增加 `tested_targets` 与 `handover`。

每个 `checks` 项包含 `requirement_id`、`result`、`evidence_ids`，必要时补充 `notes`。

- `complete`：所有在本次范围内的必需检查均有可核验真实证据，没有 `fail / not-run / blocked`。`not-applicable` 必须解释原因，不能用于跳过未实现需求。
- `blocked`：必要账号、平台、设备、用户步骤或审核结果缺失；逐项列出 `reason` 与可执行的 `next_action`。
- `failed`：已执行检查发现不符合验收要求，且当前尚未修复。
- `skipped`：仅当用户明确取消这一阶段或交付范围确实不需要时使用，并说明不能据此声称完成验证。

模拟演练可以产出验收计划，但不能标记产品验证完成。主技能负责检查证据引用、登记状态和决定下一步，本 Skill 不直接写调度状态文件。
